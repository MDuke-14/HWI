# RCA — "Folha de Horas" PDF fails to open in production only

**App:** timesync-app-2 · run `5106296c-bc33-4691-bd34-608999524de5` (active, healthy) · farm template · **Cloudflare frontend** (`/api/*` proxied through the Cloudflare Worker to the k8s backend; preview hits the pod directly — this is the ONLY environmental difference).

## Verdict
**(a) Truncated / altered response body at the Cloudflare edge.** NOT (b) HTML error saved as .pdf, NOT (c) missing font/asset, NOT (d) reportlab exception — all three ruled out below.

## The actual failing endpoint
The admin button in `/app/frontend/src/components/AdminTimeEntries.jsx` `handleDownloadPDF` (line 418) calls **`GET /api/time-entries/reports/monthly-pdf`** — NOT `custom-range-pdf` as originally suspected. Both endpoints share the identical defect, and `custom-range-pdf` (line 2591) internally reuses the same `generate_monthly_pdf_report` + same response shape, so the fix must cover both.

## Evidence gathered
1. **Server-side generation is sound (verified in eph pod).**
   - `generate_monthly_pdf_report` is in `/app/backend/pdf_report.py:85`; it builds into a `BytesIO`, and at line 413 does `buffer.seek(0)` before `return buffer` — so the buffer is correctly rewound (not an empty-stream bug).
   - Pinned `reportlab==4.4.4`. Installed it in-pod and ran the same SimpleDocTemplate→BytesIO path: output is a valid, COMPLETE PDF — `head=b'%PDF-1.4'`, `tail=b'%%EOF'`, non-zero length. Generation does not truncate or error.
2. **(c) missing font/asset — RULED OUT.** The monthly path uses only built-in Helvetica; the only external assets are PNG logos (`backend/assets/hwi_logo.png`, `hwi_logo_dark.png`) which are present and baked into the image. No `TTFont`/`registerFont`/`.ttf` in the monthly path. No `/tmp` writes.
3. **(d) reportlab exception / 500 — RULED OUT.** The endpoint wraps generation in `try/except` that logs `"Erro PDF: ..."` and raises HTTP 500. Prod logs over 24h show NO `Erro PDF`, NO traceback, and the PDF routes return **200 OK** (e.g. repeated `folha-horas-pdf` 200s). The backend is emitting a valid PDF.
4. **(b) HTML/JSON error masqueraded as .pdf — RULED OUT (for the non-2xx case).** `handleDownloadPDF` checks `if (!response.ok) throw` BEFORE `response.blob()`, so a 4xx/5xx would surface a toast error, not a saved-but-broken .pdf. The frontend is correct and byte-identical across preview/prod, so it is not the differentiator.
5. **Live capture caveat.** I could NOT capture prod status/content-type/first-bytes with a valid admin token — the endpoint requires auth (unauthenticated probe → `403 {"detail":"Not authenticated"}`), and the eph sandbox has no app secrets. So the edge truncation is **diagnosed from architecture + a concrete code differential**, not reproduced end-to-end. Generation soundness itself WAS reproduced in-pod.

## Root cause (the code differential)
`monthly-pdf` and `custom-range-pdf` return the PDF as a raw streamed body with **no `Content-Length`**:

`/app/backend/routes/time_entries.py:2044` (monthly-pdf) and `:2617` (custom-range-pdf):
```python
return StreamingResponse(
    pdf_buffer,                       # a BytesIO
    media_type="application/pdf",
    headers={"Content-Disposition": f"attachment; filename={filename}"}
)
```
A FastAPI `StreamingResponse` with no `Content-Length` is emitted with `Transfer-Encoding: chunked`. In preview the browser talks straight to the pod and receives the full chunked stream. In production the same stream is re-proxied by the Cloudflare Worker; a chunked binary with no declared length is the classic case that gets buffered/re-encoded/truncated at the edge, yielding a body that no longer ends at `%%EOF` → PDF reader shows *"Falha ao carregar o documento PDF."*

**Corroboration inside the same codebase:** the PDF endpoints that WORK set an explicit length — `/app/backend/routes/relatorios.py:3098-3103` returns `StreamingResponse(..., headers={"Content-Disposition":..., "Content-Length": str(size)})`. The broken ones are exactly the ones missing that header.

## Fix (SOURCE change — apply in the preview/source env, then redeploy)
Return a fixed-length response with an explicit `Content-Length` (mirrors the working `relatorios.py` endpoints). In `/app/backend/routes/time_entries.py`, for BOTH `download_monthly_pdf_report` (~line 2044) and `download_custom_range_pdf` (~line 2617):

```python
from fastapi.responses import Response  # add to imports

pdf_bytes = pdf_buffer.getvalue()       # buffer already seek(0)'d by generator
filename_ascii = filename  # ensure ASCII/no spaces, or use filename*=UTF-8'' form
return Response(
    content=pdf_bytes,
    media_type="application/pdf",
    headers={
        "Content-Disposition": f'attachment; filename="{filename_ascii}"',
        "Content-Length": str(len(pdf_bytes)),
    },
)
```
This makes the response a complete, length-declared binary the Cloudflare Worker forwards intact. (Same pattern should be applied to any other `application/pdf` StreamingResponse lacking `Content-Length`, e.g. `relatorios.py:2614`.)

## How to confirm after fixing
With a valid admin token: `curl -sD - -o /tmp/x.pdf "https://timesync-app-2.emergent.host/api/time-entries/reports/monthly-pdf?month=..&year=..&user_id=.." -H "Authorization: Bearer <token>"` — response should now carry `Content-Length` (no `Transfer-Encoding: chunked`), `head -c8 /tmp/x.pdf` == `%PDF-1.` and the file opens.
